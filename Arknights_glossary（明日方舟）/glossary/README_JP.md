# アークナイツ 多言語用語集

## [中文](README.md) [English](README_EN.md)

**目標言語**ごとにフォルダー、**20 分類**ごとにファイルで構成した対訳用語集です。簡体字中国語、繁体字中国語、英語、日本語、韓国語を収録しています。

## ディレクトリ構造

```
Arknights_glossary（明日方舟）/
├── glossary/                 # 用語集データ製品
│   ├── README.md             # 本説明（tools/write_readme.py が生成）
│   ├── zh-CN/                # 目標言語 = 簡体字中国語
│   │   ├── 01_干员名称.csv
│   │   ├── 02_干员异格.csv
│   │   ├── ...
│   │   ├── 20_游戏机制.csv
│   │   └── _all.json         # 上記 20 ファイルの統合版（JSON）
│   ├── zh-TW/   （同構造）
│   ├── en-US/   （同構造）
│   ├── ja-JP/   （同構造）
│   └── ko-KR/   （同構造）
├── tools/                    # 生成スクリプトとメタデータ
│   ├── build_glossary.py     # _data/gamedata を読み、glossary/ を出力
│   ├── write_readme.py       # _summary.json に基づき glossary/README.md を生成
│   └── _summary.json         # 分類ごとの語彙数とカバレッジ統計
└── README.md                 # ゲーム総説（中国語）
```

## ファイル形式

各 CSV は 3 列で、UTF-8 BOM エンコード（Excel でそのまま開けます）：

| source | target | tgt_lng |
| ------ | ------ | ------- |
| Amiya | 阿米娅 | zh-CN |
| アーミヤ | 阿米娅 | zh-CN |
| 阿米婭 | 阿米娅 | zh-CN |
| 아미야 | 阿米娅 | zh-CN |

- `target`：そのファイルが属する目標言語における公式訳名。
- `tgt_lng`：目標言語タグ。所属フォルダー名と同じ。
- `source`：同じ語彙の**他の 4 言語**での表記（したがって同じ語彙が複数行に現れます）。
  例えば `zh-CN/01_干员名称.csv` の「阿米娅」は、`Amiya`（en-US）、`アーミヤ`（ja-JP）、
  `阿米婭`（zh-TW）、`아미야`（ko-KR）を source とする 4 行として現れます。

> 「英→中」のような一方向の語彙表だけを残したい場合は、`source` の言語で絞り込むだけです。例えば source がラテン文字の行だけを残します。

## データソースとバージョン

- メインデータ：[ArknightsAssets/ArknightsGamedata](https://github.com/ArknightsAssets/ArknightsGamedata)
  —— 各地区サーバー公式クライアントの展開済みテーブル。`cn` / `tw` / `en` / `jp` / `kr` の 5 区が併存しテーブル構造も同一で、本用語集の基礎です。
- クロスチェック：[ArchyCillp/ArknightsTranslationContrast](https://github.com/ArchyCillp/ArknightsTranslationContrast)
  —— オペレーター/スキル訳名のサンプル照合に使用。
- 構造参考：[flandia/ArknightsGameDataComposite](https://github.com/flandia/ArknightsGameDataComposite)
  —— 4 言語のみ（繁体字中国語なし）で項目もメインデータより少ないため、データソースとしては用いず、比較のみに使用。

各サーバーのバージョン（`data_version.txt`）：

- 簡体字中国語 `rel77.0`（2026/08/31）
- 英語 `51.4.0`
- 繁体字中国語 `50.8.0`

> 各区服の進行度が異なるため、最新の内容が日/英/韓/繁体字中国語ではまだ実装されていない場合があり、それらの語彙は
> 用語集に現れません（生成時に少なくとも 2 言語が同時に存在することを要求します）。

## 生成方法

1. **ID による対応付け**：すべてのテーブルは項目 ID（`char_002_amiya`、`skchr_amiya_2` など）をキーとし、
   5 区服の同一 ID の値を 1 組にまとめ、同じ概念の公式訳名であることを保証します。
2. **名称系の分類**は公式フィールドをそのまま取得します（オペレーター名、スキル名、ステージ名、敵名など）。
3. **説明系の分類**（スキル説明の重要用語、一部のゲームメカニクス）は**プレースホルダー分割 + 全コーパス投票**を採用：
   ゲームテキスト中の `<@ba.vup>`、`{atk:0%}` などのマークは各言語で完全に同一なので、マークでテキストを分割すれば
   構造が揃った断片が得られます。さらに同一の中国語断片について各言語で最も多く現れる表記を集計し、語順の違いによるずれを解消します。
4. **クリーニング**：リッチテキストタグ、改行、対になった引用符と二重山括弧を除去し、数字のみ/記号のみの断片を除外。

## 既知の制限

- 説明系の用語（05、20）はテキストから自動抽出したもので、一部の項目は厳密な用語ではなく句の断片のままです。必要に応じた人手による確認を推奨します。
- ステージやイベントなど同名の項目が多いもの（例：「标准实战环境」）はそれぞれ別行になり、項目をまたぐ統合は行っていません。
- オペレーターの異格は異格形態そのもののみを収録しています。基本オペレーターは `01_干员名称` を参照してください。

## 再現

```
python tools/build_glossary.py     # <ゲームルート>/_data/gamedata を読み、<ゲームルート>/glossary/ を出力
python tools/write_readme.py       # tools/_summary.json に基づき本ファイルを再生成
```

> `_data/gamedata` は外部データディレクトリ（各区服公式クライアントの展開済みテーブル）で、**リポジトリには同梱されていません**。
> 「データソースとバージョン」の節に従って事前に用意しないと再現できません。
