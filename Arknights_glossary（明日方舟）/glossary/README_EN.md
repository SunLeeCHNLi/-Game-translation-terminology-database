# Arknights Multilingual Terminology Database

## [中文](README.md) [日本語](README_JP.md)

A translation terminology database organised by **target language** into folders and by **20 categories** into files, covering Simplified Chinese, Traditional Chinese, English, Japanese and Korean.

## Directory Structure

```
Arknights_glossary（明日方舟）/
├── glossary/                 # Glossary data product
│   ├── README.md             # This document (generated by tools/write_readme.py)
│   ├── zh-CN/                # Target language = Simplified Chinese
│   │   ├── 01_干员名称.csv
│   │   ├── 02_干员异格.csv
│   │   ├── ...
│   │   ├── 20_游戏机制.csv
│   │   └── _all.json         # Merged version of the above 20 files (JSON)
│   ├── zh-TW/   (same structure)
│   ├── en-US/   (same structure)
│   ├── ja-JP/   (same structure)
│   └── ko-KR/   (same structure)
├── tools/                    # Generation scripts and metadata
│   ├── build_glossary.py     # Reads _data/gamedata, writes glossary/
│   ├── write_readme.py       # Generates glossary/README.md from _summary.json
│   └── _summary.json         # Entry counts and coverage statistics per category
└── README.md                 # Game overview (Chinese)
```

## File Format

Every CSV has three columns and is UTF-8 BOM encoded (Excel can open it directly):

| source | target | tgt_lng |
| ------ | ------ | ------- |
| Amiya | 阿米娅 | zh-CN |
| アーミヤ | 阿米娅 | zh-CN |
| 阿米婭 | 阿米娅 | zh-CN |
| 아미야 | 阿米娅 | zh-CN |

- `target`: the official translation in the target language to which the file belongs.
- `tgt_lng`: the target language tag, equal to the name of the containing folder.
- `source`: how the same entry is written in the **other 4 languages** (so the same entry appears in multiple rows).
  For example, in `zh-CN/01_干员名称.csv` the entry「阿米娅」appears as 4 rows, with `Amiya` (en-US), `アーミヤ` (ja-JP),
  `阿米婭` (zh-TW) and `아미야` (ko-KR) as the source respectively.

> If you only want a one-way list such as "English → Chinese", simply filter by the language of `source` — for example, keep only the rows whose source uses the Latin alphabet.

## Data Sources and Versions

- Main data: [ArknightsAssets/ArknightsGamedata](https://github.com/ArknightsAssets/ArknightsGamedata)
  — unpacked official client tables for each regional server; the `cn` / `tw` / `en` / `jp` / `kr` regions coexist with an identical table structure and form the basis of this glossary.
- Cross-check: [ArchyCillp/ArknightsTranslationContrast](https://github.com/ArchyCillp/ArknightsTranslationContrast)
  — used for spot-checking operator/skill translations.
- Structural reference: [flandia/ArknightsGameDataComposite](https://github.com/flandia/ArknightsGameDataComposite)
  — has only 4 languages (no Traditional Chinese) and fewer entries than the main data, so it was not used as a data source, only for comparison.

Versions of each server (`data_version.txt`):

- Simplified Chinese `rel77.0` (2026/08/31)
- English `51.4.0`
- Traditional Chinese `50.8.0`

> Because the regional servers progress at different rates, the latest content may not yet be live in Japanese/English/Korean/Traditional Chinese,
> and such entries do not appear in the glossary (generation requires at least two languages to be present at the same time).

## Generation Method

1. **Alignment by ID**: all tables use the entry ID (such as `char_002_amiya`, `skchr_amiya_2`) as the key,
   grouping the values of the same ID across the 5 regional servers to guarantee that they are official translations of the same concept.
2. **Name-type categories** take the official field directly (operator names, skill names, stage names, enemy names, etc.).
3. **Description-type categories** (skill description key terms, some game mechanics) use **placeholder segmentation + whole-corpus voting**:
   markers such as `<@ba.vup>` and `{atk:0%}` in the game text are identical across all languages, so splitting the text on them yields
   structurally aligned fragments; the most frequent spelling in each language is then counted for the same Chinese fragment, eliminating mismatches caused by word-order differences.
4. **Cleaning**: remove rich-text tags, line breaks, paired quotation marks and book-title marks, and filter out purely numeric/purely symbolic fragments.

## Known Limitations

- The description-type terms (05, 20) are mined automatically from text; a few entries are still phrase fragments rather than strict terms, so manual review is recommended as needed.
- Entries such as stages and events that share the same name in large numbers (for example「标准实战环境」) each get their own row; no cross-entry merging has been done.
- Operator alters include only the alter form itself; see `01_干员名称` for the base operators.

## Reproduction

```
python tools/build_glossary.py     # Reads <game root>/_data/gamedata, writes <game root>/glossary/
python tools/write_readme.py       # Regenerates this file from tools/_summary.json
```

> `_data/gamedata` is an external data directory (the unpacked official client tables of each regional server) and **is not distributed with the repository**;
> it must first be prepared as described in the "Data Sources and Versions" section before reproduction is possible.
