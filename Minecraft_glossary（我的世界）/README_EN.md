# Minecraft Terminology Database / 《我的世界》翻译术语库 / Minecraft 用語集

## [中文](README.md) [日本語](README_JP.md)

This directory holds a multilingual terminology database for **Minecraft**, built from the **official Minecraft: Java Edition language files**. It covers 34 categories — blocks, items, entities, biomes, enchantments, status effects, advancements, subtitles, GUI and options and more — across **14 target languages** and **1,420,443** aligned rows; a supplementary Minecraft Wiki name-standardisation glossary adds **10,314** rows for 2 Chinese target languages. The main glossary text is the game's own official localisation, so it is **official localisation data rather than a second-hand translation**; the supplement follows the Minecraft Wiki's name-standardisation page, which is kept in sync with the localisation agreed on Crowdin. Everything is stored as three-column `source,target,tgt_lng` CSV files that import directly into terminology tools such as Immersive Translate.

## Usage

1. **Download a single file**: open the target-language folder (for example `minecraft-glossary/zh-CN/`; system and text categories live in that folder's `extra/` subfolder), and download the one category file you need, such as `blocks.csv`, `items.csv` or `extra/subtitles.csv`. It can be imported straight into Immersive Translate or any other tool that accepts a term list.
2. **Download a whole language folder**: grab one language folder (for example `minecraft-glossary/ja-JP/`) and pick the category files you want from it. The supplement lives in the `minecraft-glossary-supplement/zh-CN/` and `minecraft-glossary-supplement/zh-TW/` folders.
3. **Clone the repository and reproduce it yourself**: together with the scripts in `tools/` and the upstream repositories listed under "Related Sources", you can regenerate every CSV and metadata file (see "Regeneration").

## Regeneration

```bash
# 1) Main glossary: build the 14 languages × 34 categories from the official language files
python tools/build_glossary.py

# 2) Supplement: build the 13 categories for zh-CN / zh-TW from both variants of the Wiki page
python tools/build_wiki_supplement.py

# 3) Regenerate the Chinese README of both sub-glossaries from the two metadata files
python tools/make_readme.py

# 4) Verify: row-by-row checks of header, tgt_lng, empty values and duplicate rows, plus the metadata row counts
python tools/verify_output.py
```

Notes:

- Both build scripts **read an external source directory** (`SRC_DIR = E:\Download\BT\Codex_input` by default; edit the constant in a text editor to point at your own copy):
  `build_glossary.py` needs `mcmeta_lang/<locale>.json` (take it from the `assets` branch of mcmeta), and
  `build_wiki_supplement.py` needs wiki_std_cn.json / wiki_std_tw.json in that source directory (the rendered result of that page's `action=parse&prop=text&variant=zh-cn|zh-tw`; the file names are defined by `SRC_DIR` in `tools/build_wiki_supplement.py`).
  This source data is not part of this repository and has to be prepared separately.
- Generated metadata is written to `tools/glossary_counts.json` and `tools/supplement_counts.json`; the scripts no longer write metadata into the glossary data folders.
- The whole pipeline uses the **Python standard library only** (`json` / `os` / `csv` / `re` / `html` / `collections`) — no Node.js and no third-party packages, Python 3.8+ is enough.
- The scripts derive the game root from their own location, so always invoke them with the `tools/` prefix, for example `tools/verify_output.py` from inside the game folder.
- All CSVs are **UTF-8 with BOM**, **CRLF** line endings, with a `source,target,tgt_lng` header row and RFC 4180 quoting when a field contains a comma or quote; the explanatory Markdown files are UTF-8 without BOM.
- Cleaning rules: rows identical to the target language are dropped (for example untranslated track titles and proper nouns); duplicate rows produced by the same entry are merged; empty or missing translations produce no row; format placeholders (`%s`, `%1$s`, `%%`) are kept verbatim; duplicate translations of the same key across languages are deduplicated by `source`+`target`.
